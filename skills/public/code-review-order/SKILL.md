# 代码审查 Skill

## 概述

接收用户提交的代码，进行结构化分析并输出审查报告。

## 触发条件

当用户说以下内容时触发：
- "帮我审查代码"
- "代码审查"
- "review code"
- "帮我看看这段代码"
- "代码有问题"
- "检查一下代码"
- "代码检查"
- "帮我review代码"
- "code review"
- "看看这段代码"
- "代码优化建议"
- "重构建议"
- "代码质量分析"
- "技术债务分析"
- "code audit"
- "代码审计"

## 执行流程

### Step 1：接收代码输入

用户可以通过以下方式提供代码：
1. **直接粘贴**：用户将代码粘贴到对话中
2. **上传文件**：用户上传代码文件（.py, .js, .java, .cpp, .go, .rs 等）

如果用户只说了"审查代码"但没有提供具体代码，需要礼貌询问：
> 请提供需要审查的代码，你可以直接粘贴代码或上传代码文件。

### Step 2：识别编程语言

根据代码内容或文件后缀识别编程语言：
- Python: `.py`, 缩进敏感, `def`, `import`
- JavaScript: `.js`, `.jsx`, `function`, `const`, `let`
- Java: `.java`, `public class`, `System.out`
- C/C++: `.c`, `.cpp`, `#include`, `int main`
- Go: `.go`, `package`, `func`
- Rust: `.rs`, `fn main`, `let mut`

如果无法识别，明确询问用户。

### Step 3：执行代码审查

按以下维度进行分析：

#### 3.1 语法正确性
- 语法错误检查
- 括号/引号匹配
- 缩进一致性

#### 3.2 代码风格
- 命名规范（变量、函数、类）
- 代码格式
- 注释完整性

#### 3.3 逻辑问题
- 潜在 bug
- 边界条件处理
- 异常处理

#### 3.4 安全问题
- SQL 注入风险
- XSS 漏洞
- 敏感信息泄露
- 不安全的随机数/加密

#### 3.5 性能问题
- 时间复杂度
- 空间复杂度
- 内存泄漏风险
- 数据库查询效率

#### 3.6 最佳实践
- 设计模式应用
- 代码复用
- 模块化程度

### Step 4：生成审查报告

输出格式如下：

```markdown
## 📋 代码审查报告

**语言**: {编程语言}
**代码行数**: {行数}

### ✅ 优点
- {优点1}
- {优点2}

### ⚠️ 需要改进
| 严重程度 | 问题 | 位置 | 建议 |
|---------|------|------|------|
| 🔴 高 | 问题描述 | 行号 | 修改建议 |
| 🟡 中 | 问题描述 | 行号 | 修改建议 |
| 🟢 低 | 问题描述 | 行号 | 修改建议 |

### 📝 总体评价
- **可读性**: X/10
- **安全性**: X/10
- **性能**: X/10
- **总分**: X/10

**总结**: {一句话评价}
```

### 边界情况处理

| 情况 | 处理方式 |
|------|----------|
| 代码太短（<5行） | 提示"代码过短，难以进行完整审查" |
| 代码太长（>500行） | 建议分批审查或指出重点关注部分 |
| 不支持的编程语言 | 告知"暂不支持该语言审查"，列出支持的语言 |
| 无法识别的代码 | 询问用户代码语言 |

## 支持的语言

- Python (包括 Python 2.x 和 3.x)
- JavaScript/TypeScript (Node.js, 浏览器)
- Java (包括 JDK 8+)
- C/C++ (C99, C++11+)
- Go
- Rust
- PHP (PHP 7.0+)
- Ruby
- Swift
- Kotlin
- C#
- HTML/CSS (前端代码)
- SQL (数据库查询)

## 输出要求

- 报告使用中文
- 问题按严重程度排序
- 每条问题给出具体的修改建议
- 如果有代码示例，提供修正后的代码片段
